# 第七批离线工具设计提案（已实施）

状态：**已确认并完成开发**。

提案阶段已经对照当时 `AGENTS.md` 中的工具清单和 `lib/tools/tool_registry.dart` 的 41 个稳定 ID。比较依据是实际操作流程，而不是名称、图标或页面布局。

## 1. GitHub 调研结论

本轮优先筛选能够完全离线、无需账号、无需新增 Android 权限，并且适合单页完成的工具：

- `fluttercandies/toto` 展示了基于 Base32 密钥生成 TOTP/HOTP 的成熟流程，包括 SHA-1/SHA-256/SHA-512、位数和周期配置。
- `capytoolkit/capytoolkit` 的工程计算工具包含“输入电压、电流、电阻、功率中的任意两项，求其余两项”的欧姆定律流程。
- `awesome-yasin/supercalculator` 收录了欧姆定律和统计计算器，说明这两类工具适合轻量工具箱的独立工作流。
- `tasnimultas67/toolstrek` 收录了整数与罗马数字双向转换工具。

这些仓库仅作为功能和交互调研来源；实现时不会复制其代码，也不会把网络、账号或远程脚本带入应用。

## 3. 重复检查

### TOTP 验证码

- 不等同于“哈希生成”：虽然 TOTP 内部使用 HMAC，但主要流程包含 Base32 密钥、基于设备时间的计数器、动态截断、位数和剩余秒数。
- 不等同于“密码生成”：它不生成静态随机密码，而是从已有密钥计算短时有效验证码。
- 第一版不导入二维码、不保存账户、不扫描相机，避免与二维码工具混淆并减少密钥暴露面。

### 欧姆定律

- 不等同于“计算器”：输入模型是四个物理量中选择两个，输出另外两个，并处理量纲关系。
- 不等同于“单位换算”：它进行公式推导，而不是把同一物理量转换单位。
- 属于已有规范允许的“具有独立输入模型和工作流的专用计算器”。

### 统计计算

- 不等同于“文本工具”的字符、单词、行数统计；本工具统计的是数值数据集。
- 不等同于“列表处理”的排序、去重、打乱；这些操作不会计算均值、中位数和标准差。
- 第一版不加入图表、回归或概率分布，保持边界清晰和计算轻量。

### 罗马数字

- 不等同于“进制转换”：罗马数字不是二、八、十、十六进制这类位值制数字系统，且需要规范形式校验。
- 第一版只支持常用规范范围 1–3999，不支持 0、负数、小数和加横线扩展记法。

## 5. 页面设计与交互

四个页面沿用已确认的工具详情页基线：白色卡片、浅灰背景、深绿色主按钮、Material 字体图标、顶部返回栏；不新增底部主导航，不使用图片类工具图标和高成本动画。

### 5.1 TOTP 验证码

- 密钥输入框默认遮挡，提供“显示/隐藏”字体图标。
- 配置项使用轻量下拉控件：算法、位数、周期。
- 主操作为“生成验证码”；结果卡显示分组后的验证码和剩余秒数。
- 复制必须由用户主动点击；密钥与验证码均不写入日志、偏好、文件或剪贴板历史管理逻辑。
- 页面离开时清理输入和定时器。设备时间不准确时结果也会不准确，页面需要明确提示。

### 5.2 欧姆定律

- 顶部选择“已知量”的组合；页面只启用两项输入，另外两项作为结果。
- 输入支持常见 SI 前缀，结果同时展示标准单位与可读缩放值。
- 主操作为“开始计算”；结果卡显示电压、电流、电阻、功率和关系式。
- 拒绝空值、负值、非有限数以及会导致除零的组合。

### 5.3 统计计算

- 多行输入支持英文逗号、空格和换行分隔数字。
- 主操作为“计算统计”；结果用紧凑两列卡片展示。
- 输入上限 100 KB、最多 10,000 个有限数字；使用稳定的在线算法计算方差，避免大列表中间值造成不必要误差。
- 样本数不足 2 时不显示样本标准差，并给出中文说明。

### 5.4 罗马数字

- 顶部使用“数字转罗马 / 罗马转数字”分段选择。
- 主操作为“转换”；结果卡显示结果、规范形式说明和主动复制按钮。
- 罗马输入统一转为大写后严格校验规范形式；像 `IIII`、`VX` 这类非规范表示应报错，而不是静默修正。

## 6. 安全与性能边界

- 全部计算在设备本地执行，不申请网络、相机、存储或通知权限。
- 输入必须先做长度、数量、范围和有限值校验，用户错误只显示可处理的中文提示。
- TOTP 密钥属于敏感临时数据：不持久化、不记录日志、不自动复制；倒计时只每秒更新结果局部组件并在 `dispose()` 中停止。
- 统计计算由显式按钮触发；如果基准测试显示低端设备上 10,000 个数字影响帧率，再移入 isolate。
- 四个工具分别放入自己的 `lib/tools/<tool_name>/` 目录，并且只在 `tool_registry.dart` 注册一次。

## 7. 确认后的开发顺序

用户确认设计后，按以下顺序逐个实现和检查：

1. TOTP 验证码。
2. 欧姆定律。
3. 统计计算。
4. 罗马数字。
5. 同步更新 `AGENTS.md` 工具清单和必要的 README。
6. 依次执行 `dart format`、`flutter analyze --no-pub`、`flutter test --no-pub`；仅在依赖或 Android 配置发生变化时追加正式 APK 构建。
